# Как мы работаем с кодом

Правила общие для всех репозиториев CaravanHouse. Они короткие, но соблюдаем их всегда.

## 1. Ветки

`main` — рабочая версия, её автоматически деплоим. Напрямую в `main` не пушим.

Каждая задача делается в отдельной ветке от свежего `main`:

| Префикс | Для чего | Пример |
| --- | --- | --- |
| `feature/*` | новая функция | `feature/booking-form` |
| `fix/*` | исправление ошибки | `fix/header-mobile-menu` |

Имена веток пишем латиницей, в нижнем регистре, через дефис.

```bash
git switch main
git pull
git switch -c feature/booking-form
```

## 2. Коммиты: Conventional Commits

Формат: `тип: что сделано` (коротко, в повелительном наклонении, можно на английском или русском).

| Тип | Когда |
| --- | --- |
| `feat` | новая функция |
| `fix` | исправление ошибки |
| `docs` | документация |
| `style` | форматирование, без изменения логики |
| `refactor` | переписали код, поведение не изменилось |
| `perf` | ускорение |
| `test` | тесты |
| `chore` | зависимости, настройки, мелочи |

Примеры:

```text
feat: add Payme payment to checkout
fix: close mobile menu on link click
docs: update README setup steps
```

Одна логическая правка — один коммит. Секреты, токены и `.env` не коммитим никогда.

## 3. Pull Request: единственный путь в `main`

1. Запушьте ветку: `git push -u origin feature/booking-form`.
2. Откройте Pull Request в `main` и заполните шаблон.
3. Убедитесь, что сборка и проверки проходят (`npm run build`, `npm run lint`).
4. Попросите коллегу посмотреть изменения.
5. После одобрения нажмите **Squash and merge**, и ветка удалится.

Заголовок PR тоже пишем в стиле Conventional Commits: он станет сообщением коммита в `main`.

## 4. Задачи (Issues)

Баги и идеи заводим через шаблоны **Bug report** и **Feature request**. В PR ссылаемся на задачу: `Closes #12`.
